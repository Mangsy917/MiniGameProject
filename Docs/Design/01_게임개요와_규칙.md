# 게임 개요와 규칙

## 개요

- **장르**: 메이드 인 와리오 형식의 하이퍼 캐주얼 미니게임 모음
- **플랫폼**: 스마트폰, 터치, 싱글플레이
- **핵심 경험**: 4~5초짜리 미니게임을 빠르게 연속으로 깨는 긴장감과 "한 판 더"
- **팀**: 기획 1, 프로그래밍 1, 아트 6 (+ 지도교수)

## 용어

| 용어 | 뜻 | 코드 |
|---|---|---|
| 스테이지 | 테마 하나(사막, 정글, …)의 판. 스테이지 선택 화면에서 고른다 | `StageNumber`, 스테이지 씬 |
| 라운드 | 스테이지 안에서 미니게임 하나를 하는 단위 | `Round` |

## 핵심 규칙 (기획 확정)

1. 목숨 4개로 시작하고, 4개를 넘을 수 없다.
2. 1라운드 = 미니게임 1개. 기본 제한시간 5초.
3. 제한시간 안에 클리어하면 바로 다음 라운드로 넘어간다. 실패하면 목숨 1 감소.
4. 목숨이 0이 되면 게임 오버.
5. 제한시간은 5.0 → 4.5 → 4.0초로 줄고, 4.0초 아래로는 내려가지 않는다.

## 스테이지 진행 (2026-11-20 확정)

- 스테이지 선택 화면에서 플레이어가 스테이지를 고른다.
- 사막, 정글, 동굴, 절벽, 숲 5개 스테이지는 처음부터 모두 열려 있다.
- 5개 스테이지를 모두 클리어하면 연구소 스테이지가 열린다.
- 각 스테이지에서는 그 테마의 미니게임 중에서 랜덤으로 나온다 (지금은 우선제작 5개). **직전에 나온 미니게임은 바로 다시 나오지 않는다.**
- **스테이지는 20라운드. 20라운드를 마쳤을 때 목숨이 남아 있으면 스테이지 클리어. 마지막(20) 라운드에서 실패해도 목숨이 남아 있으면 클리어로 인정한다.** (2026-11-20 확정)
- 20라운드도 10의 배수라 특수 라운드(체력회복 찬스)다.
- (스테이지 선택, 연구소 해금, 직전 제외 랜덤은 현재 코드에 이미 구현되어 있다: `StageProgress.IsLabStageUnlocked()`, `StageFlowController.PickGame()`)

## 무한 모드 (2026-11-20 확정)

- 연구소 스테이지를 클리어하면 열린다 (현재 코드와 같음: `StageProgress.IsInfinityModeUnlocked()`).
- **6개 테마의 미니게임이 모두 랜덤으로 섞여 나온다** (지금은 우선제작 30개). 직전에 나온 미니게임은 제외.
- 목숨이 0이 될 때까지 계속한다. 10라운드마다 특수 라운드 규칙은 같다.
- **점수(클리어한 라운드 수)는 무한 모드에서만 보여 준다.** 스테이지 모드에서는 점수를 표시하지 않는다.

## 특수 라운드: 체력회복 찬스와 스피드업 (2026-11-20 확정)

보스는 없다. 대신 10라운드 주기로 체력회복 찬스와 스피드업이 이어서 나온다. 전용 미니게임은 없고, 두 라운드 모두 일반 미니게임이 나온다.

**진행 순서 (10라운드 기준, 20·30·… 라운드도 같음)**

```
9라운드 종료
→ 10라운드 시작 + 체력회복 찬스 연출
→ 10라운드 플레이 (원래 속도)
    ├ 클리어: 목숨 +1 (최대 4)
    └ 실패: 목숨 −1
→ 스피드업 연출 (기존 SpeedUpUI "SPEED UP!")
→ 11라운드 시작 (제한시간 −0.5초)
```

- 체력회복 찬스 연출은 10라운드가 시작될 때 나온다. 연출 내용(문구·이미지)은 아트·UI 작업에서 정한다.
- 스피드업 연출과 제한시간 감소는 10라운드의 성공·실패와 관계없이 적용된다.
- 스테이지 모드는 20라운드가 마지막이라, 20라운드 뒤에는 스피드업 연출 없이 스테이지가 끝난다.

**제한시간 표**

| 라운드 | 제한시간 |
|---|---|
| 1 ~ 10 | 5.0초 |
| 11 ~ 20 | 4.5초 |
| 21 ~ (무한 모드) | 4.0초 |

- 하한은 **일단 4.0초로 고정**한다. 나중에 더 빨라질 수 있으므로 하한값은 인스펙터에서 바꿀 수 있게 둔다.
- 하한에 도달한 뒤(무한 모드 30, 40, … 라운드 뒤)에는 제한시간이 더 줄지 않으므로 스피드업 연출을 생략한다.

## 지시문 (2026-11-20 확정)

- 대기 화면(라운드 숫자와 목숨 표시)이 끝난 뒤 미니게임이 시작되면, **지시문은 미니게임 화면 안에 계속 떠 있다** (만져라 메이드 인 와리오 스타일).
- 지시문을 보여 주는 별도 시간은 없다. 지시문은 제한시간이 흐르는 동안 함께 보인다.
- 지시문 텍스트는 `MiniGame.Title`에 넣는다.

## 점수 (2026-11-20 확정)

- 점수 = **클리어한 라운드(미니게임) 수**. 실패한 라운드는 세지 않는다.
- 무한 모드에서만 표시한다.

## 테마

| 순서 | 테마 | 영문 | 성격 |
|---|---|---|---|
| 1 | 사막 | Desert | 탐험 |
| 2 | 정글 | Jungle | 탐험 |
| 3 | 동굴 | Cave | 탐험 |
| 4 | 절벽 | Precipice | 탐험 |
| 5 | 숲 | Forest | 탐험 |
| 6 | 연구소 | Laboratory | 탐험에서 가져온 발견물을 연구. 1~5 클리어 후 해금 |

테마마다 미니게임 20개, 총 120개를 기획했다. **이 중 우선제작 30개(테마별 5개)만 지금 만든다** (`Priority/` 폴더). 나머지 90개는 후순위로 만들지 않는다. 전체 기획안은 `MiniGames/` 폴더.

## 미니게임 설계 원칙

- 시작하자마자 필요한 요소가 모두 화면에 놓여 있고, 기다리지 않고 순발력으로 빠르게 깨는 방식을 우선한다.
- 지시문은 1~2단어. 동작형은 "~해라!", 화면의 정보를 보고 답을 고르는 유형은 의문문 "~은?".
- 기억해서 따라 하는 유형은 만들지 않는다.
- 징그러운 소재(거머리, 벌레 떼, 뱀 등)는 피한다. (일부 기존 미니게임에는 남아 있음)
- 로직이 같고 그림만 다른 미니게임을 허용한다. 다양성은 아트로 만든다.
- 수치(대상 개수, 연타 횟수, 속도 기준)는 데이터로 빼서 기획자가 플레이테스트로 조정한다.

## 끝나는 조건

| 조건 | 의미 | 코드 |
|---|---|---|
| 빨리깨기 | 목표를 달성하면 즉시 성공. 시간이 끝나면 실패 | `SucceedOnTimeUp = false`, 달성 시 `Finish(true)` |
| 버티기 | 시간이 끝날 때까지 실패하지 않으면 성공 | `SucceedOnTimeUp = true`, 실패 조건에서 `Finish(false)` |

우선제작 30개 중 버티기 4개(DES_01, JUN_04, CAV_09, FOR_14), 빨리깨기 26개.

## 현재 코드에서 바꿔야 할 것

지금 `StageFlowController`는 보스 구조(10라운드 중간보스, 20라운드 최종보스, 중간보스 이후 5초 → 4초, 최종보스 실패 시 재도전, "MID BOSS!"/"FINAL BOSS!" 연출)로 되어 있다. 기획에 맞추려면 아래처럼 바꾼다.

1. 보스 미니게임 고정(`MidBossGame`, `FinalBossGame`)과 보스 등장 연출(`BossIntroUI`)을 없앤다. 모든 라운드는 `NormalGames`에서 랜덤.
2. 10의 배수 라운드(10, 20, 30, …)는 체력회복 찬스: 라운드 시작 때 체력회복 찬스 연출(새 UI, 기존 보스 등장 연출 자리를 활용 가능), 클리어 시 목숨 +1(최대 `MaxLife`), 실패 시 목숨 −1.
3. 체력회복 찬스 라운드가 끝나면(성공·실패 무관) 스피드업 연출(`SpeedUpUI`)을 보여 주고, 다음 라운드부터 제한시간 −0.5초. 하한 4.0초는 인스펙터 값으로 두고, 하한에 도달한 뒤에는 스피드업 연출을 생략 (현재: 중간보스 이후 4초 고정 → 5.0 / 4.5 / 4.0으로 변경).
4. 스테이지 모드는 20라운드를 마치면(20라운드 실패해도 목숨이 남아 있으면) 스테이지 클리어. 최종보스 실패 시 재도전 로직은 삭제하고, 20라운드 뒤에는 스피드업 연출 없이 끝낸다.
5. 무한 모드는 등록된 미니게임 전체(지금은 30개)에서 랜덤, 목숨이 0이 될 때까지 계속, 클리어한 라운드 수를 점수로 표시.

위 작업은 기획자가 요청하면 진행한다.
